# DS-1000
**Type:** Measurement  
**Referenced in:** 18 papers  

## State of the Field

**What it is.** Papers most commonly describe DS-1000 as a benchmark of 1000 data science coding problems, workflows, or challenges, usually spanning seven widely used Python libraries such as NumPy and Pandas. The prevailing framing is data science code generation, though some definitions narrow this to code completion of partial snippets, and one description adds two evaluation modes, completion and insertion. Several papers also describe the problems as real-world StackOverflow questions with unit tests or test cases, while one paper characterizes them as non-standalone functions with contextual dependencies.

**What it is claimed to measure.** Across the surveyed work, papers use DS-1000 to measure code generation, and it is linked to one behavioral indicator and no constructs. The claims concentrate on that single indicator: authors describe tasks as generating Python code for data science questions written in natural language, using standard data science libraries, and passing executable test cases. Some papers frame the same use more specifically as data science code completion.

**Space of uses.** No measurement instrument is linked to DS-1000. In use, papers often place it alongside other code benchmarks, especially HumanEval, HumanEval+, MBPP, MultiPL-E, and CRUXEval, as part of broader evaluation suites. In those settings it is presented as the data science-oriented benchmark, and one paper specifically uses it to evaluate code reasoning and library-usage capabilities.

**Concerns raised.** A smaller line of work raises a scope concern: DS-1000 is said not to specially test a model's ability to satisfy implicit API constraints, and instead to focus on applying data science APIs to solve data analysis tasks.
